vulnerability_parser.py

Nessus CSV to Executive Excel & SLA Breakdown

Script que ingiere reportes pesados en formato CSV/XML de Nessus o Qualys, consulta de forma asíncrona la API de FIRST para obtener el score EPSS, clasifica por SLA y exporta un informe estructurado en Excel con tablas dinámicas y colores por criticidad. 

# Enriquecimiento automático con EPSS y filtrado SLA
import pandas as pd
import requests

def fetch_epss(cve_id):
    url = f"https://api.first.org/data/v1/epss?cve={cve_id}"
    resp = requests.get(url, timeout=5).json()
    return float(resp['data'][0]['epss'])

df = pd.read_csv("nessus_raw_scan.csv")
criticals = df[df['Risk'].isin(['Critical', 'High'])].copy()
criticals['EPSS'] = criticals['CVE'].apply(fetch_epss)
criticals.to_excel("Prioritized_Remediation_Report.xlsx")

CIS Benchmark Baseline Auto-Audit

Herramienta ligera sin agentes para servidores Linux/Windows. Valida políticas de contraseñas, permisos de archivos críticos (`/etc/shadow`, permisos sudoers), deshabilitación de protocolos obsoletos (TLS 1.0/1.1, SMBv1) y genera una bitácora en JSON listo para SIEM. 

#!/usr/bin/env bash
# CIS Baseline check para /etc/passwd y SSH Hardening
echo "[*] Checking SSH Protocol configuration..."
if grep -q "^PermitRootLogin no" /etc/ssh/sshd_config; then
    echo '{"check": "ssh_root_login", "status": "COMPLIANT"}' >> audit.log
else
    echo '{"check": "ssh_root_login", "status": "NON_COMPLIANT"}' >> audit.log
fi

NEW FRONTIER > ARTIFICIAL INTELLIGENCE SECURITY

SecAI: Seguridad en Inteligencia Artificial & LLMs

Protección de infraestructuras de aprendizaje automático, gobernanza de modelos fundacionales (LLMs), mitigación de ataques adversariales y cumplimiento de las directivas OWASP Top 10 for LLMs.

¿Por qué SecAI es prioritario hoy?

La integración de agentes de IA y modelos generativos introduce nuevos vectores donde el texto no confiable se convierte en código ejecutable.

Dominios Clave de Protección en IA Generativa

LLM01:2025 Riesgo Alto

Prompt Injection (Directo e Indirecto)

Manipulación de instrucciones del sistema a través de entradas maliciosas o contenido web no verificado ingestando por agentes de IA.

🛡️ Mitigación: Separación estricta de contexto, guardrails semánticos y validación de outputs.
LLM02:2025 Fuga de Datos

Sensitive Information Disclosure

Extracción no autorizada de datos confidenciales, llaves API, contraseñas o PII memorizados en pesos del modelo o buffers de contexto.

🛡️ Mitigación: Sanitización de datasets de entrenamiento y filtros regex/DLP en respuestas.
LLM04:2025 Integridad

Data & Model Poisoning

Alteración intencionada de la data con la que se fine-tunean modelos corporativos para crear puertas traseras lógicas (backdoors).

🛡️ Mitigación: Verificación criptográfica de hashes de dataset y control estricto de procedencia.
LLM06:2025 Agentes

Excessive Agency / Acceso Excesivo

Permitir que un modelo o agente ejecute acciones irreversibles (borrado de base de datos, envío de correos, transacciones) sin intervención humana.

🛡️ Mitigación: Principio de menor privilegio (PoLP), Human-in-the-Loop y tokens acotados.
LLM03:2025 Supply Chain

Supply Chain (modelos y dependencias ML)

Uso de modelos pre-entrenados de repositorios públicos (ej: Hugging Face) que contengan pickle exploits o serializaciones arbitrarias de código.

🛡️ Mitigación: Escaneo de pesos con herramientas como Safetensors y ModelScan.
GOVERNANCE NIST AI RMF

Framework de Riesgos NIST AI RMF

Implementación de los cuatro pilares: Govern, Map, Measure y Manage para sistemas de IA confiables, robustos y auditables.

🛡️ Mitigación: Auditorías periódicas de sesgo, robustez adversarial y evaluación de impacto.

Arquitectura Defensiva para Aplicaciones LLM (RAG Seguro)

En un flujo típico de Retrieval-Augmented Generation (RAG), se implementan barreras en cada etapa:

1. ENTRADA

Guardrails, límites de tokens y detección de Prompt Injections (NeMo / LlamaGuard).

2. VECTOR DB

Control de acceso basado en roles (RBAC) en la base de datos vectorial; cifrado en reposo.

3. MODELO

System Prompt con aislamiento explícito y políticas de 'Do not override base instructions'.

4. SALIDA

Filtro DLP para detectar claves secretas o PII antes de renderizar la respuesta al usuario.
